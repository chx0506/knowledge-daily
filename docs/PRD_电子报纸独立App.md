# 电子报纸独立 App 产品 PRD

**文档版本**：V1.0  
**日期**：2026-09-13  
**产品形态**：独立 iOS / Android App，兼容桌面小组件与平板横屏  
**产品定位**：基于 AI 编排热点信息、提供个性化阅读与原文深度跳转的电子报纸产品

## 1. 项目背景

用户每天需要从多个平台获取热点、行业动态和感兴趣领域的信息。现有信息流产品内容丰富，但存在信息过载、推荐不可控、来源分散和阅读目标不明确等问题。本产品以“每日可读的一份电子报纸”为核心体验，由 AI 将公开热点与用户订阅领域内容进行筛选、摘要、编排和版式设计，并通过小组件把摘要入口前置到桌面。

会议已确认产品独立运行，不强制依赖知乎或其他内容平台；产品可以对接知乎、抖音、小红书等数据源，第一阶段聚焦电子报纸主产品线，暂不投入游戏与工作台方向。

## 2. 产品目标与非目标

### 2.1 产品目标

1. 让用户在 3–5 分钟内完成一次高质量的热点浏览。
2. 通过 AI 自动完成热点聚合、去重、摘要、分类和版式编排。
3. 让用户能明确控制阅读领域、推荐数量和信息深度。
4. 通过免费额度 + 个性化增值位实现可持续商业化。
5. 通过原文跳转保留信息来源，提升内容可信度和后续深读效率。

### 2.2 非目标

- 第一阶段不建设完整的社交关系链、评论社区或创作者发布平台。
- 不替代数据源平台的完整内容消费体验。
- 不在 V1 建设游戏化产品线和通用工作台。
- 不承诺覆盖所有热点来源，优先保证来源质量、摘要准确性和稳定更新。

## 3. 用户与核心场景

### 3.1 目标用户

- **泛热点用户**：希望快速了解当天重要事件。
- **垂直领域用户**：关注科技、商业、投资、职场、文化等具体领域。
- **高频信息工作者**：需要固定时间接收结构化行业简报。
- **轻阅读用户**：希望通过桌面小组件获得低打扰的信息提醒。

### 3.2 核心场景

- 早晨打开 App，阅读今日电子报纸。
- 午间通过桌面小组件浏览当天热点摘要，并点击进入完整报纸。
- 用户订阅多个领域，分别查看不同报纸栏目。
- 看到摘要后点击标题，跳转至知乎等来源页面查看原文。
- 免费额度用尽后，购买额外个性化推荐位或订阅套餐。

## 4. 产品范围与版本规划

### V1（MVP）

- 独立 App 基础框架与账号体系。
- 今日电子报纸生成、阅读、刷新和历史查看。
- 热点聚合、AI 摘要、分类、去重、排序和版式编排。
- 个性化领域选择和默认 3 个推荐位。
- 超额个性化推荐位单次付费。
- 多领域订阅。
- 标题点击跳转原文。
- 桌面小组件展示每日热点摘要。
- 竖屏、横屏及平板适配。
- 内容来源标注、反馈和基础举报能力。

### V1.1

- 推送通知和定时送达。
- 报纸收藏、分享和稍后阅读。
- 关键词屏蔽、主题权重调整。
- 更多数据源接入与来源健康监控。

### V2

- 个性化版式主题和阅读风格。
- 语音播报、离线阅读和跨设备同步。
- 面向机构或团队的领域报纸套餐。
- 基于用户反馈的摘要质量自适应优化。

## 5. 信息架构

1. **首页 / 今日报纸**：当天报纸、栏目导航、推荐位状态、来源信息。
2. **领域**：领域列表、订阅管理、领域报纸切换。
3. **发现**：未订阅领域、热门主题和推荐报纸。
4. **历史**：按日期查看已生成报纸。
5. **我的**：账号、付费权益、推荐偏好、通知、隐私与反馈。

## 6. 核心功能需求

### 6.1 首次启动与兴趣设置

**目标**：在不增加复杂配置的情况下完成首次个性化。

- 首次启动展示产品价值说明和隐私/来源说明。
- 用户选择至少 1 个、最多 10 个关注领域。
- 可选填关键词、屏蔽词和内容偏好（国内/全球、深度/简洁）。
- 系统默认发放 3 个个性化推荐位。
- 未完成设置时，使用“全球热点 + 综合推荐”生成默认报纸。
- 设置可随时修改；修改后下一次生成报纸生效。

### 6.2 电子报纸生成

**输入**：数据源文章、发布时间、热度、来源质量、用户领域偏好、历史已读/跳过记录。  
**输出**：一份包含头版、领域栏目和热点摘要的电子报纸。

处理流程：

1. 定时抓取或接收数据源内容。
2. 清洗标题、正文摘要、图片、作者、发布时间和原文 URL。
3. 进行相似内容聚类和重复合并。
4. AI 识别主题、领域、事件实体和情绪倾向。
5. 按热度、时效性、来源可信度和用户偏好排序。
6. 生成摘要、关键事实、相关背景和原文跳转入口。
7. 生成版式结构，校验字段完整性后发布。

生成规则：

- 每篇摘要默认 80–150 字；重要头条可扩展至 250 字。
- 摘要必须包含事件主体、核心事实和时间信息；无法确认的信息需标记“待核实”。
- 同一事件只保留一个主卡片，其他来源作为“相关来源”。
- 不能生成原文不存在的事实、数字、引述或结论。
- 无有效来源 URL 的内容不得进入可点击发布状态。
- 当日内容不足时，展示“内容较少”提示，并补充最近 24 小时内的相关内容。

### 6.3 报纸阅读与交互

- 头版展示日期、报纸名称、生成时间和更新时间。
- 栏目包括：今日头条、全球热点、已订阅领域、编辑精选（可配置）。
- 卡片支持展开/收起、标记已读、收藏、分享和反馈。
- 点击标题或“查看原文”跳转来源页面，优先使用 App 内 WebView，失败时调用系统浏览器。
- 对跳转失败提供重试、复制链接和查看其他来源入口。
- 支持下拉刷新；刷新有频率限制，避免重复消耗生成额度。
- 支持字体大小、深色模式、阅读密度设置。

### 6.4 个性化推荐位与付费

**免费基础**：默认包含 3 个个性化推荐位及世界热点总结。  
**付费进阶**：超过默认数量的个性化推荐位按单次或套餐购买。

推荐位定义：用户指定的一个“领域/主题/关键词”在当日报纸中的独立编排位置。

- 免费用户可查看 3 个推荐位的配置和当日内容。
- 用户新增第 4 个推荐位时，展示价格、权益和支付按钮。
- 支付成功后立即解锁，支持当日重生成一次。
- 购买记录、权益有效期和剩余推荐位在“我的”中可查。
- 支付失败不扣减权益；重复支付需幂等处理。
- 退款按支付渠道规则执行，退款后对应权益回收。

价格由运营后台配置，PRD 只定义计费逻辑，不固定具体金额。

### 6.5 多领域订阅

- 用户可订阅多个领域，每个领域可设置优先级：高 / 中 / 低。
- 领域报纸支持独立查看，也支持合并到“今日总报纸”。
- 领域可包含二级主题和关键词。
- 支持暂停订阅、删除订阅和恢复默认推荐。
- 订阅变更后给出预计下次生效时间，避免用户误以为历史报纸即时变化。

### 6.6 桌面小组件

- 提供小、中、大三种尺寸（以系统能力为准）。
- 展示内容：报纸标题、更新时间、1–3 条热点摘要、来源标识。
- 点击整体进入今日报纸；点击单条进入对应文章详情或原文。
- 小组件每日自动更新，更新失败展示最近一次成功内容及时间。
- 用户可选择展示“综合热点”或某一订阅领域。
- 小组件不展示付费墙，点击进入 App 后再处理权益校验。
- 视觉方向可采用类似《新世纪福音战士》的信息编排感，但需单独完成商用字体、图片和素材授权评估，不直接复用受版权保护的素材。

### 6.7 内容反馈与质量控制

- 每篇内容提供“有帮助 / 不准确 / 不感兴趣 / 重复”反馈。
- “不准确”需要选择问题类型：事实错误、摘要偏差、来源失效、其他。
- 用户反馈进入质量队列，支持人工抽检和模型评估。
- 内容被标记为高风险或多次不准确时，自动下线并触发重新生成。
- 展示内容来源、发布时间和“AI 生成摘要”标识。

## 7. 后台与运营能力

### 7.1 内容后台

- 数据源管理：新增、停用、健康状态、抓取频率、授权信息。
- 主题与领域管理：领域树、同义词、屏蔽词和排序权重。
- 报纸审核：预览、抽检、发布、撤回、重新生成。
- 内容追溯：查看摘要对应的原文片段、模型版本和生成日志。

### 7.2 商业化后台

- 推荐位价格、套餐、活动和有效期配置。
- 订单、支付、退款、权益发放与回收。
- 用户权益查询和异常补发。

### 7.3 数据看板

- 日活、次日留存、报纸打开率、完整阅读率。
- 原文点击率、小组件曝光/点击率。
- 领域订阅数、推荐位转化率、付费率、ARPPU。
- 摘要反馈率、错误率、来源失效率、生成成功率。

## 8. 关键页面与交互说明

### 8.1 首页

顶部显示日期与更新时间；首屏展示头条卡片和“今日报纸已准备好”状态。向下依次展示栏目、个性化推荐位和来源列表。推荐位不足时，在最后一个免费位后展示弱提示式升级入口。

### 8.2 文章详情页

展示 AI 摘要、关键事实、相关来源、原文标题、作者、发布时间和跳转按钮。原文不可用时，显示失效原因和备用来源，不展示无来源的“推测内容”。

### 8.3 领域管理页

以标签和分组方式展示已订阅领域。每个领域可调整优先级、关键词和是否出现在小组件。保存后提示生效时间。

### 8.4 付费页

明确展示：已使用推荐位、免费剩余推荐位、购买数量、价格、有效期、退款规则和支付渠道。支付前必须展示订单确认页，支付完成后回到原触发页面。

## 9. 技术与数据要求

### 9.1 推荐与生成服务

- 采用任务队列异步生成报纸，前端轮询或通过推送获取状态。
- 生成状态：排队中、生成中、校验中、已发布、失败。
- 失败自动重试 2 次；仍失败时展示上一版报纸并说明更新时间。
- 模型服务需支持版本记录、提示词版本记录和可回放日志。

### 9.2 核心数据对象

- User：用户基础信息、设备、隐私同意状态。
- Preference：领域、关键词、屏蔽词、推荐位配置。
- Source：平台、来源 URL、授权状态、健康状态。
- Article：原文元数据、内容指纹、聚类 ID、质量状态。
- Newspaper：日期、用户/领域、生成状态、模型版本、发布时间。
- NewspaperItem：摘要、排序、版式、原文关联、反馈统计。
- Entitlement：免费额度、购买权益、有效期、消耗记录。
- Order：订单、支付状态、退款状态和幂等号。

### 9.3 隐私与合规

- 明确告知数据来源、AI 生成机制和个性化推荐使用范围。
- 最小化采集用户信息；兴趣偏好支持导出和删除。
- 记录用户对隐私政策、服务协议和付费规则的同意版本。
- 数据源接入遵守平台开放接口、robots、版权和内容使用规则。
- 支持未成年人保护、内容举报和违规内容下架流程。

## 10. 非功能指标

- 首页首屏可交互时间：P95 ≤ 3 秒（已有报纸）。
- 报纸生成成功率：≥ 99%。
- 生成任务完成时间：常规报纸 P95 ≤ 5 分钟。
- 原文跳转成功率：≥ 98%。
- 小组件日更新成功率：≥ 99%。
- 付费订单最终一致性：支付回调后 60 秒内完成权益到账。
- 关键接口可用性：月度 ≥ 99.9%。
- AI 摘要事实错误率：上线前离线评测 ≤ 1%，线上持续监控并按周抽检。

## 11. 埋点方案

事件包括：首次启动、兴趣设置完成、报纸打开、栏目曝光、卡片展开、原文点击、原文跳转成功/失败、收藏、分享、反馈提交、增加推荐位、支付发起、支付成功/失败、订阅新增/删除、小组件曝光/点击、报纸生成成功/失败。

关键漏斗：

1. 安装 → 完成兴趣设置 → 首次打开报纸。
2. 报纸打开 → 卡片展开 → 原文点击 → 原文成功打开。
3. 免费推荐位用尽 → 付费页曝光 → 支付发起 → 支付成功。
4. 小组件曝光 → 进入 App → 完整阅读。

## 12. 验收标准

- 用户能完成注册、兴趣设置并生成一份可阅读报纸。
- 报纸包含至少一个头条、至少一个来源 URL 和更新时间。
- 同一事件重复文章能被合并，并保留相关来源。
- 任何摘要卡片均可查看来源并跳转原文。
- 免费用户默认获得 3 个个性化推荐位；超额操作能正确触发购买流程。
- 支付成功、失败、重复回调、退款场景下权益状态正确。
- 多领域订阅、暂停、删除和恢复流程可用。
- 小组件三种尺寸至少有一种在目标系统版本上稳定展示并可点击进入 App。
- 横屏、竖屏和平板布局无关键内容遮挡或不可操作问题。
- 内容来源、AI 标识、隐私政策和用户反馈入口完整可见。

## 13. 发布计划

### 阶段一：技术验证（2 周）

完成数据源样例接入、AI 摘要链路、报纸数据结构和原文跳转验证。

### 阶段二：MVP 开发（6–8 周）

完成 App 核心页面、生成服务、个性化配置、支付权益、小组件和后台基础能力。

### 阶段三：灰度与优化（2 周）

邀请种子用户，重点验证摘要准确性、阅读完成率、推荐位价值感和付费转化。

### 阶段四：正式发布

按平台审核要求提交，持续监控内容质量、崩溃率、生成成功率和支付链路。

## 14. 风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 数据源授权或接口变化 | 内容中断 | 多源冗余、健康监控、降级到公开可用来源 |
| AI 摘要事实错误 | 信任和合规风险 | 原文约束、事实校验、人工抽检、快速下线 |
| 内容版权边界不清 | 下架或投诉 | 仅展示必要摘要，保留来源和跳转，完成授权评估 |
| 用户不理解推荐位收费 | 转化低、投诉 | 在首次设置和付费页解释推荐位定义、额度和有效期 |
| 生成延迟过高 | 阅读体验下降 | 异步任务、缓存、上一版报纸兜底 |
| 小组件更新受系统限制 | 信息过期 | 展示更新时间，失败时保留最近一次成功内容 |

## 15. 待确认事项

1. 首发平台优先级：iOS、Android 是否同步，最低系统版本是多少。
2. 首发数据源及授权方式，是否已有知乎等平台的接口权限。
3. 免费 3 个推荐位的具体定义，以及超额推荐位的定价和有效期。
4. 是否支持手机号、第三方账号或匿名试用。
5. 报纸生成频率：每日一次、每 6 小时一次，还是用户主动刷新。
6. 视觉风格参考的具体边界、字体与素材授权方案。
7. 付费渠道、发票、退款和地区化价格策略。
8. 内容审核由人工、模型还是两者结合，目标审核时效是多少。
